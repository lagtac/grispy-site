Saving and filling a form

Save a form under a name, keep as many sets of answers against it as you need, and bring any of them back in one click.

Grispy starts empty, and that is the mechanic rather than a fault. It has nothing to offer on a form it has never seen. You teach it a form once — by filling that form in yourself and pressing Save — and from then on it can fill that form for you, with whichever set of answers you pick.

What the popup shows when you open it

Click Grispy's toolbar button on any page. It reads the page there and then — it is not watching in the background — and shows one of these:

Scanning page… Reading the page. Normally a moment.
12 fields found The ordinary case. Below this line is everything else on this page.
No form fields found on this page. Grispy read the page and there was nothing it recognised as a form field.
Cannot access this page. Some pages are closed to every extension — your browser's own settings pages, the extension gallery, and files it has not been given access to.
This page has saved data You have set a passphrase and this is the first time this browser session that Grispy needs it. See protecting your saved data.

Saving a form for the first time

  1. Fill the form in yourself, the way you normally would. Grispy saves what is in the fields, so it has to be there first.
  2. Open Grispy and press Save. The popup switches to a list of every field it found, each with the value currently in it.
  3. Choose what to keep. Everything starts ticked. Untick anything you do not want stored — a one-off reference number, a comment, anything you would rather not have written to disk at all. Select all at the top toggles the lot.
  4. Press Confirm Save. Grispy answers Saved 12 fields for this page.

The first thing you ever save also brings up one question about encrypting what Grispy stores. It is asked once, you can decline, and it does not come back.

Filling it back in

Go back to the same form later and open Grispy. Because it recognises the page, the popup now shows a Fill button and a line saying when this set of answers was saved:

Saved 14/08/2026The date this preset was last written.
Saved 14/08/2026 · 3 fields changed Three fields you saved are no longer on the page. Usually the form changed. The rest still fill.
No fields match current page Grispy has this page on file but recognises none of the saved fields on it. On a form that spans several pages this usually means you are on a different step, and the status line just above the buttons is where you say so.

Press Fill and Grispy writes the answers back, then checks each one and tells you what it managed. That message is worth understanding — what a fill reports explains it in full.

More than one set of answers for the same form

This is the part your browser's autofill cannot do. Autofill knows one identity: one name, one address, one card. Grispy holds as many sets against a single form as you need, each under a name you choose. They appear as a row of chips at the top of the popup.

  1. The first thing you save becomes a preset called Default.
  2. Press the + chip to start another. Grispy names it Save 2, then Save 3, and so on.
  3. Fill the form in with the new answers and press Save. Those answers go to the new preset; Default is untouched.
  4. Click any chip to switch. The chip you click becomes the active one, and Fill uses it. Grispy remembers which one you had selected per form.

Renaming and deleting

Once you have two or more presets, a ⋯ button appears beside the saved date with Rename and Delete in it. It is hidden with only one preset because neither action does anything useful there, and Delete stays disabled on the last remaining preset rather than leaving a form with none.

Deleting a preset is immediate and cannot be undone. To remove a whole form, or everything at once, use the Settings page.

What saving again does

Saving over a preset replaces what it holds for the page you are on. On a form spanning several pages, the other pages' answers are untouched — each page is stored separately under the same preset.

Two saves are worth knowing about before you make them:

  • A save with fields unticked drops them. If a field was saved before and you untick it now, its stored value goes.
  • A save on a page showing fewer repeating rows than you saved would discard the rows that are not on screen, so Grispy asks first rather than doing it. That question is explained here.

Known limits

  • It acts only when you click it. Grispy never fills on page load. That is the same choice that lets it ask for no standing access to any website — it can read a page only after you invoke it, on the tab you invoked it on.
  • Some fields it cannot see. Rich-text editors, fields built inside a web component's shadow DOM, and custom pickers with no ordinary form control underneath are invisible to it. They cannot be saved and cannot be filled.
  • A form is identified by its address. Grispy keys what it saves to the site and path of the page, ignoring anything after the ?. Two genuinely different forms at one address need the step controls to tell them apart.
  • Nothing syncs. What you save stays in this browser on this computer. To move it, export and import a file.
