Details that fit any form

A named set of details belongs to no form, so Grispy has something to offer on a form it has never seen.

Everything else in this guide starts with a form you have saved. This page is about the other half. A set of details holds facts by what each one is — an email, a phone number, a postcode — rather than by which box it sat in on some form you filled once. An email is an email on every portal, so a set of details can be aimed at a form Grispy has never seen before.

It does not remove the cold start; it moves it. Grispy still holds nothing when you install it. What changes is that you teach it once, ever instead of once per form.

Where they are in the popup

Open Grispy on any page and there are two rows of chips, each with a label above it. The labels are the only thing that tells them apart, so they are worth reading:

This form The sets of answers saved against this form. Empty and hidden until you have saved this form at least once. Covered in saving and filling a form.
Any form Your sets of details. Always shown, even before you have any, because it is the way in to everything on this page.

The last chip on the Any form row always opens the full list. What it says depends on how many you have:

No presets yetYou have none. Click it anyway — this is where you make the first one.
All detailsYou have some, and they all fit on the row.
4 moreYou have more than six. The row shows the six you made most recently; this opens the whole list, with a box to filter it by name.
LockedYou have set a passphrase and have not entered it yet. Your details are encrypted, so Grispy cannot read their names. More.

Making your first set

There are three ways in, and the first is the one to start with.

Learn it from a form you have just filled in

  1. Fill a form in yourself — any form that holds the details you want to keep. Grispy reads values off the page, so they have to be on it.
  2. Open Grispy, click the last chip on the Any form row, then Learn from this page at the bottom of the list.
  3. Read the list. Every field on the page is shown with the detail Grispy thinks it holds, the reason it thinks so, and the value it would keep.
  4. Correct anything wrong with the dropdown on the row, and untick anything you do not want stored.
  5. Name the set — a client, an applicant, yourself — and press Save details.

Nothing is written until you press that button. This is deliberate and it is not the same caution as saving a form. A wrong saved form is recoverable and affects one form; a wrong detail is copied into every form you fill afterwards, looking entirely plausible in each of them.

The reason on each row is the useful part when something looks wrong:

The page's own autocomplete says this field is “email”. The strongest evidence there is. The page told Grispy what the field is for.
The field is named “tel”. Taken from the field's own name in the page's markup.
The field is labelled “Postcode”. Taken from the words you can see beside the field.
You mapped this field to this detail on this form. You corrected it before, on this form. Your correction wins over everything above.
Nothing on the page named this field. Grispy has no idea what this field holds. Set it yourself, or leave it.

Promote a set of answers you have already saved

If you have saved this form before, the ⋯ menu beside the saved date has Promote to global preset in it. It opens the same review list, filled from the answers that preset holds for the page you are on rather than from what is on screen.

It needs you to be on the form's page: Grispy re-reads the live page to work out what each saved answer is, and a stored copy does not carry enough to do that. It covers the step you are looking at, not every page of a multi-step form.

Type one in from scratch

Open Settings → Details & sets → Sets → New set. You get a name field and two lists: on the left, every detail Grispy knows about, grouped under headings and narrowed by a filter; on the right, the set itself, which starts empty. Press Add beside a detail to put it in the set, then fill in the value. A set holds what you put in it and nothing else. Nothing needs a form open.

Filling with one

Click a chip on the Any form row and it fills with colour. Above the buttons, a line appears saying what Fill is about to do — before you press anything:

Fill writes 6 of 14 fields. Contract is not applied.
Fill writes 6 of 14 fields. 14 is every field Grispy found on this page. 6 is how many it can match to a detail this set actually holds. The other 8 are left exactly as they are.
Contract is not applied. Only when this form also has its own saved answers. It names the preset that is not being written, so the highlighted chip is never ambiguous.
2 fields on this page cannot be written into yet. Grispy matched the field and holds a value, but cannot put that value into that particular control.
2 fields are left blank: this form asks for the same detail about more than one person. The form has two boxes for the same thing — two surnames, two tax numbers. Grispy will not guess which one is yours, so it fills neither. Type those two yourself.

Press Fill and it behaves exactly as a normal fill does, including the chips it paints beside each field and the message it reports afterwards — what a fill reports.

Only one thing is ever selected

Across both rows of chips, exactly one chip is ever filled with colour, and that one is what Fill writes. Clicking a set of details deselects the form's own preset, and clicking the filled details chip again clears it and hands the selection back. There is no order to remember and no combining: one chip, one Fill, one source.

If a form needs both, fill the form's own preset first and the set of details last. Two fills, in that order.

A preset saved on a form you filled for someone else still carries their name and phone number alongside the form's boilerplate. Do it the other way round — details first, then that preset — and the second fill writes the earlier subject's name over the one you just put in, in a live portal, with nothing on screen afterwards saying it happened. Details last is safe because the details are what you want to win. The chips a fill paints mark a field as written; they never say what was there before. The line above the buttons naming the preset that is not applied is the only warning you get, and it is only there before you press Fill.

What a browser restart does

A selected set of details is forgotten when the browser closes. A form's own preset is not — Grispy remembers that per form, indefinitely.

This is on purpose: a set of details may be about somebody who is not you, and carrying that selection into tomorrow, unwatched, is not something Grispy does. The cost is that the same popup on the same page can fill something different after a restart, which is why the chip is filled with colour before you press anything. Read the chip, not your memory of yesterday.

Details Grispy does not know about

Grispy ships a fixed list of details — names, contact details, address parts, a few profile links — and you can add your own from Settings → Details & sets. Press New detail and type the name; it belongs to no set until you put it in one. While you are filling a set, typing a name the Grispy knows about filter does not have offers to create it there instead, and that one goes straight into the set. Two things to know before you do:

  • A detail you add matches nothing on its own. The shipped ones are recognised because Grispy knows what they are usually called. Yours has no such history, so it reaches a field only after you point at that field once — see below.
  • A detail you add can be renamed, but not deleted. A typo is recoverable; an unwanted one stays in the list. Deleting one would strand any value saved against it, and the machinery to find and report that does not exist yet.

Pointing at a field without saving its value

On a form you have saved, open the same list — the last chip on the Any form row, then Learn from this page — and press Just map the fields at the top. The values disappear and you are left with the fields and their dropdowns. Set the ones you care about and confirm: Grispy remembers that this field on this form is that detail, permanently, and writes no values at all.

This needs a form Grispy has already saved, because the mapping is kept alongside that form. On a page it does not know, the button is replaced by a line saying so.

Where they are kept

  • In this browser, on this computer, like everything else Grispy holds. Nothing is sent anywhere.
  • Encrypted, if you have set a passphrase — sets of details and the details you add are both covered by it. More.
  • Edited and deleted from Settings → Details. The popup can create a set by learning one; it can delete nothing. Deletion is kept on a page you do not have open all day.
  • Included in an export, and restored by an import. A restore otherwise replaces everything, but a backup taken before 4 September 2026 holds no details at all, so restoring one leaves yours alone rather than wiping them.

Known limits

  • It fills what it recognises, not everything. How much of an unfamiliar form fills is set by which details Grispy knows about, not by how hard it tries. Six of fourteen is a normal result and not a failure.
  • It never guesses. A field it cannot identify, or holds no value for, is left exactly as the page had it. A fill never blanks a field it did not write.
  • Two people on one form defeat it. Where a form asks for the same detail about more than one person, both are left blank rather than one being filled at random.
  • A set of details cannot hold a form's own answers. Dropdown choices, tickboxes, dates specific to one application — those live in that form's own preset. The two are different tools and most real work uses both.
